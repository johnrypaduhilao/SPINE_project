To satisfy the intent **"Protect the sensitive files at this path"** for `/srv/app/config`, the system can derive a set of concrete security policies. Each policy should contribute to preserving the confidentiality, integrity, and availability of the files.

| Policy                            | What it does                                                                                 | Why it follows from the intent                                                                  |
| --------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Restrict read access              | Allow only authorized users, services, or processes to read files under `/srv/app/config`.   | Sensitive files often contain secrets or configuration data that should not be disclosed.       |
| Restrict write access             | Permit modification only by trusted administrators or authorized deployment processes.       | Protecting sensitive files includes preventing unauthorized changes or tampering.               |
| Restrict execute permissions      | Remove execute permission unless a file explicitly requires it.                              | Configuration files generally should not be executable, reducing attack surface.                |
| Apply least-privilege permissions | Grant each user or service only the minimum access necessary.                                | Minimizes the risk of accidental or malicious misuse while still allowing legitimate operation. |
| Protect directory traversal       | Prevent unauthorized users from listing or traversing the directory contents.                | File names and directory structure may themselves reveal sensitive information.                 |
| Enforce ownership                 | Ensure files and directories are owned by the appropriate system account(s).                 | Proper ownership supports reliable enforcement of access controls.                              |
| Audit access                      | Log successful and failed access attempts to the directory and its contents.                 | Auditing helps detect unauthorized access and supports incident investigation.                  |
| Audit modifications               | Record file creation, modification, deletion, and permission changes.                        | Changes to sensitive configuration should be traceable to preserve integrity.                   |
| Protect secrets at rest           | Encrypt particularly sensitive files or the underlying storage where appropriate.            | If storage is compromised, encryption helps preserve confidentiality.                           |
| Validate integrity                | Detect unauthorized modifications using checksums, signatures, or file integrity monitoring. | Protection includes ensuring files remain unaltered except by authorized changes.               |
| Secure backups                    | Ensure backups of `/srv/app/config` are encrypted and subject to equivalent access controls. | Sensitive information remains sensitive in backup copies.                                       |
| Prevent accidental deletion       | Require elevated authorization or safeguards before deleting protected files.                | Availability is part of protecting important configuration.                                     |
| Limit process access              | Allow only approved applications or services to access the directory when possible.          | Reduces exposure if unrelated processes are compromised.                                        |
| Monitor for anomalous activity    | Alert on unusual access patterns, repeated failures, or unexpected modifications.            | Early detection improves the ability to respond to attempts to compromise the files.            |
| Secure permission changes         | Restrict who can change file permissions, ownership, or ACLs.                                | Otherwise an attacker could bypass other protections by weakening access controls.              |
| Protect inherited permissions     | Ensure new files created in `/srv/app/config` inherit secure default permissions.            | Prevents newly added sensitive files from being inadvertently exposed.                          |

Together, these policies implement the intent by protecting the files' **confidentiality** (preventing unauthorized disclosure), **integrity** (preventing unauthorized modification), and **availability** (preventing accidental or malicious loss), while providing accountability through auditing and monitoring.
